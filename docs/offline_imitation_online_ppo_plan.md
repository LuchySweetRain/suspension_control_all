# Offline Imitation + Online Safe PPO Plan

Date: 2026-05-31

## Thesis Direction

The main algorithmic direction is:

**Offline-imitation-initialized online safe residual PPO for full-car active suspension control.**

The motivation is that active suspension is a continuous-control safety-critical system. A randomly initialized policy is not acceptable for online adaptation because large exploratory forces can cause poor ride comfort, actuator saturation, excessive suspension travel, or unsafe roll/pitch states. The controller should start from a reasonable expert policy and then improve conservatively during operation.

Working title:

**Safe Imitation-Initialized Residual PPO for Active Suspension Control with Road Preview Uncertainty and Actuator Dynamics**

Short name:

**SI-RPPO**

## Core Hypothesis

Compared with PPO from scratch and off-policy TD3/SAC baselines, a controller initialized by offline imitation and then optimized online with constrained residual PPO should:

- reduce early-stage unstable actions,
- improve sample efficiency during online adaptation,
- keep action changes smooth under actuator lag and rate limits,
- remain robust when road preview is delayed, noisy, biased, or partially dropped out,
- improve ride comfort without increasing suspension travel, tire-load variation, or unsafe fraction.

## Proposed Algorithmic Contributions

The project should not claim novelty from "using PPO" alone. The defensible algorithmic contribution is the combination of conservative online PPO, expert initialization, residual action structure, actuator feasibility, and preview uncertainty:

1. **Imitation-initialized online PPO for safety-critical active suspension**

   PPO starts from a behavior-cloned expert controller rather than random exploration. This targets the practical deployment setting where online adaptation must begin from a usable controller.

2. **Residual PPO around a physics/control prior**

   PPO learns only `delta_u` around `SPDF`, `LQR`, or `FULL_CAR_MPC_LITE`. The base controller handles nominal stability; PPO focuses on road- and actuator-dependent corrections.

3. **Preview-confidence and safety-margin residual gate**

   The residual update is scaled by road-preview reliability and safety margin. When preview delay/noise/dropout is high, or the vehicle is near safety limits, the learned residual is reduced.

4. **Actuator-feasible reward decomposition**

   The reward explicitly logs and penalizes action smoothness, command smoothness, saturation, actuator tracking error, energy proxy, and deviation from the prior. This turns the optimization target into an auditable control objective rather than only a scalar return.

5. **World-model / WAM extension for future work**

   A learned model can predict next state, reward components, safety risk, and feasible applied force under actuator lag. The model should be used to estimate residual risk or preview confidence, not as an uncontrolled open-loop planner.

The minimum paper-level claim should be SI-RPPO first. WAM/world-model extensions are a second-stage contribution unless the ablation evidence is already strong.

## Controller Structure

The final action is not produced directly by PPO. PPO outputs a residual correction around a safe base controller:

```text
u_t = Projection_U(
    u_base,t + alpha_t * delta_u_ppo,t
)
```

Where:

- `u_base,t` is generated by an expert or prior controller.
- `delta_u_ppo,t` is the learned residual action.
- `alpha_t` is a residual gate.
- `Projection_U` enforces actuator limits and rate feasibility.

Candidate base controllers:

- `SPDF`: available immediately and stable.
- `ReducedFullCarPreviewController`: current MPC-lite full-car prior.
- Future `LQR` or constrained preview MPC.

Current code support:

- Residual controller utilities: `controllers/prior.py`
- MPC-lite full-car prior: `controllers/reduced_full_car.py`
- Residual config: `configs/mujoco_full_car_residual.yaml`
- Full-car actuator dynamics and metrics: `envs/mujoco_full_car_env.py`

## Offline Imitation Stage

### Goal

Train an initial PPO actor by behavior cloning from expert trajectories before any online reinforcement learning.

The expert dataset should contain:

```text
observation_t
expert_action_t
next_observation_t
reward_t
done_t
info_t
```

Expert sources:

- SPDF on all default and full-car scenarios.
- Reduced full-car MPC-lite on corner-control scenarios.
- Existing good checkpoints, if available, only as secondary teachers.

Behavior cloning objective:

```text
L_BC = mean(|| pi_theta(o_t) - a_expert,t ||^2 / force_limit^2)
```

For residual PPO, the cloned target should be either:

```text
delta_u_expert,t = a_expert,t - u_base,t
```

or zero if the base controller itself is the expert:

```text
delta_u_expert,t = 0
```

Recommended implementation choice:

- First implement **direct BC PPO** for simplicity.
- Then implement **residual BC PPO** where the actor clones expert residuals.

### Acceptance Criteria

- BC-only policy can complete all benchmark scenarios without unsafe termination.
- BC-only policy has lower action saturation and action delta than PPO from scratch.
- Initial PPO online episodes start near expert performance rather than random-policy performance.

## Online Safe PPO Stage

### PPO Objective

Use PPO's clipped objective for conservative policy updates:

```text
L_clip = E[min(rho_t A_t, clip(rho_t, 1-eps, 1+eps) A_t)]
```

Add safety and actuator penalties:

```text
L = L_clip
    - lambda_safety * C_safety
    - lambda_actuator * C_actuator
    - lambda_deviation * C_deviation
```

Where:

- `C_safety`: suspension travel, pitch, roll, wheel displacement violations.
- `C_actuator`: action delta, command delta, saturation, tracking error, energy proxy.
- `C_deviation`: deviation from base controller or imitation policy.

The online PPO phase should use small updates:

- low learning rate,
- KL or clip-based update limits,
- limited online batch length,
- optional early stop if unsafe fraction rises.

## Reward Design

Use a decomposed reward, not a single opaque weighted sum.

```text
r_t = -(
    J_comfort
    + J_handling
    + J_actuator
    + J_safety
    + J_deviation
    + J_preview
)
```

### Comfort

```text
J_comfort =
    w_z    * ddz_body^2
  + w_p    * dd_pitch^2
  + w_r    * dd_roll^2
```

### Handling and Suspension Safety

```text
J_handling =
    w_s * sum(delta_y_corner^2)
  + w_t * sum(tire_load_corner^2)
```

### Actuator Feasibility

```text
J_actuator =
    w_u       * ||u_applied||^2
  + w_du      * ||u_applied,t - u_applied,t-1||^2
  + w_dcmd    * ||u_cmd,t - u_cmd,t-1||^2
  + w_track   * ||u_cmd,t - u_applied,t||^2
  + w_sat     * saturation_ratio
  + w_energy  * sum(|u_applied_i * suspension_velocity_i|)
```

Current code already exposes:

- `reward_components`
- `action_metrics`
- `action_delta_rms`
- `command_delta_rms`
- `actuator_tracking_rms`
- `saturation_ratio`

### Deviation From Expert/Base

```text
J_deviation = w_dev * ||u_final - u_base||^2
```

This term should be high at the beginning of online learning and decay as confidence improves.

### Road Preview Uncertainty

Let `c_preview` be a confidence score from delay/noise/dropout or model prediction error.

```text
J_preview = w_preview * (1 - c_preview) * ||delta_u_ppo||^2
```

This discourages aggressive residual actions when the road preview is unreliable.

## Residual Gate

The residual gate controls how much PPO is allowed to change the base controller:

```text
alpha_t = clip(alpha_min, alpha_max, sigmoid(
    beta_0
  + beta_1 * safety_margin_t
  + beta_2 * preview_confidence_t
  - beta_3 * model_error_t
))
```

Practical first version:

```text
alpha_t = alpha_config
```

Second version:

```text
alpha_t = alpha_config * preview_confidence_t * safety_margin_t
```

## World Model / WAM Extension

This is not required for the first implementation, but it is the main future algorithmic extension.

### State-Space World Model

Train a low-dimensional model:

```text
o_t, u_cmd,t, u_applied,t, road_preview_t
    -> o_t+1, reward_components_t, safety_t, u_applied,t+1
```

Loss:

```text
L_wm =
    ||o_hat_t+1 - o_t+1||^2
  + lambda_r * ||reward_components_hat - reward_components||^2
  + lambda_s * BCE(safety_hat, safety)
  + lambda_u * ||u_applied_hat_t+1 - u_applied_t+1||^2
```

### World-Action Model

A WAM-style extension predicts both future states and feasible actions:

```text
history, road_preview, control_goal
    -> future_states, residual_actions, safety_risk
```

Uses:

- initialize the residual PPO actor,
- estimate preview/model confidence,
- reject or shrink unsafe residual actions online.

Current evidence is tracked in `docs/si_rppo_experiment_log.md`.

The 2026-06-01 `episodes=20` full-scenario matrices show that the residual/prior idea is promising but still fragile. A first run supported residual learning, while the later anchor/shield-isolated run showed a deeper teacher-quality problem: using `FULL_CAR_MPC_LITE` as both expert and prior makes residual labels nearly zero, so the policy inherits a prior that is not safe across the full road benchmark. Direct BC anchoring improves return and unsafe steps over PPO scratch, but it does not yet solve action smoothness. SAC remains a strong baseline.

The current algorithm correction is safe-teacher imitation: collect expert data with raw safety statistics, optionally filter unsafe expert transitions, and allow a conservative teacher such as `PASSIVE` while keeping `FULL_CAR_MPC_LITE` as the residual prior. This turns the method from plain BC-PPO into a safer offline-to-online pipeline:

- offline data curation rejects unsafe demonstrations,
- behavior cloning initializes a feasible controller,
- residual PPO learns online improvements around an interpretable prior,
- safety gating/shielding constrains residual actions during adaptation.

The next required evidence is an improved ablation table comparing:

- PPO from scratch,
- BC-only PPO,
- BC + PPO fine-tuning,
- safe residual BC-PPO with residual gate and deviation penalty.

Most recent evidence:

```text
python scripts/run_si_rppo_ablation.py --config configs/mujoco_full_car_safe_ppo.yaml --out results/si_rppo_e20_policy_safety --episodes 20 --expert-episodes 20 --expert-controller PASSIVE --skip-unsafe-expert --baseline-algorithms td3,sac
```

This run makes `residual_prior_structure` supported again and shows that policy safety projection sharply reduces PPO unsafe drift. The remaining weakness is that PPO still optimizes the log probability of raw policy actions while the environment executes projected actions. The next algorithm revision should make the projection visible to learning:

- log raw action, projected action, projection error, and safety margin per step,
- add a projection-consistency penalty to PPO. Implemented as `projection_penalty_weight * ratio * projection_error`,
- apply this penalty to imitation-initialized PPO branches, while keeping `ppo_scratch` as a standard PPO baseline,
- optionally down-weight or clip advantages for samples whose executed action differs strongly from the sampled policy action,
- evaluate whether this turns `imitation_initialization` and `safe_residual_gate` from weak to supported.

The focused `results/si_rppo_e20_projection_core_metrics` run supports the PPO-centered core claim with explicit projection metrics. Standard PPO scratch with the same safety layer reached return `-9962.1158`, `21.0` unsafe steps, action delta `169.1610`, and projection error `0.4804`; safe-teacher BC plus projection-aware PPO reached return `-3213.2397`, `0.0` unsafe steps, action delta `80.2526`, and projection error `0.1926`. This should become the near-term main paper story. Residual RL remains a secondary extension until the prior controller is improved or replaced.
